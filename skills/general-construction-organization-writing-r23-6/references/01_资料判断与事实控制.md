# 资料判断与事实控制

## 一、九类基础资料

| 编号 | 资料 | 主要用途 | 使用边界 |
|---|---|---|---|
| ① | 招标文件 | 确定项目范围、评分、否决项、工期、格式和合同要求 | 必须结合有效澄清、答疑和补遗，不得只读摘要 |
| ② | 招标文件配套材料 | 从图纸、清单、设计文件和技术附件取得项目事实 | 核对版本、图号、位置和适用专业 |
| ③ | 高分参考文档 | 借鉴结构、深度、针对性、控制思路和表达方法 | 只作为策略源，不得提供当前项目事实 |
| ④ | 公司资料 | 在明标或招标允许区域响应人员、业绩、设备、荣誉等要求 | 暗标或身份边界未确认时隔离；只写有证明的事实 |
| ⑤ | 初始提示词 | 承载本项目或本轮任务的特殊要求 | 先核逐部位招标强制字号，允许自定处采用编前提示词。其余遵守招标硬要求。已纳入总控的信息复用 |
| ⑥ | AI评标（合肥青天大模型）分析 | 辅助理解机器评审的文本覆盖、结构和检索特征 | 不得生成事实、臆测算法或破坏正常技术逻辑 |
| ⑦ | 最新行业规范 | 提供施工、验收、质量、安全和管理依据 | 核对有效性、项目适用性及招标指定版本 |
| ⑧ | 该项目具体工程领域信息搜集 | 补足当前工程类型的技术方法、风险、工艺和验收知识 | 不得替代当前项目图纸、清单和招标事实 |
| ⑨ | 项目知识库 MD | 提供资料索引、唯一参数、评分映射、技术资料、策略、冲突和总控信息 | 是工作锚点，不是最高事实源；冲突时回查原文 |

## 二、项目知识库的最低功能

项目知识库应能定位或归纳：

1. 评分与响应清单；
2. 项目总索引及项目唯一参数；
3. 招标文件知识包；
4. 项目技术资料知识包，包括第⑧类工程领域信息；
5. 高分标书写作策略；
6. 经核验且允许使用的公司能力资料；
7. 简洁的项目总控信息；
8. 冲突与待核实事项；
9. 当前项目适用的规范和依据。

项目知识库只提炼和索引原始资料。涉及评分原文、否决项、精确数字、工程量、技术参数、图纸事实、合同条款或文件冲突时，回查原文。

## 三、资料完整性判断

不要用“有文件”代替“资料足够”。逐项判断现有资料是否足以确定：

- 工程范围、标段边界和主要施工对象；
- 结构形式、主要做法、工程量和关键参数；
- 关键施工工艺和技术路线；
- 高权重评分项所需的项目化证据；
- 工期、场地、交通、环境和专业接口约束；
- 危险性较大工程和质量安全重点；
- 暗标、篇幅、标题、文件格式和否决条件。

缺失只影响一般表述时，可继续检索或采用不依赖该信息的专业策划。图纸瑕疵或与清单冲突按下节已确定的编制口径处理并继续，不等待官方把全部资料拉通；其他缺失会改变工程范围、方法、风险、资源、评分或确定性承诺时，停止相关正式正文并集中质询。

## 四、事实来源与冲突

对具体断言按下列逻辑核验：

1. 法律法规、强制性标准和对项目有约束力的监管要求；
2. 招标文件及有效澄清、答疑、补遗；
3. 招标配套图纸、清单、设计和技术附件；
4. 经核验且允许写入当前输出区域的公司资料；
5. 经确认适用的现行或招标指定规范；
6. 从以上资料派生的项目知识库和评分清单；
7. 参考标、AI评标分析和模型推理只提供方法，不提供项目事实。

先核对是否同一对象、部位、阶段、单位和有效版本。**执行“规避它；图纸如有瑕疵或与清单冲突的话以清单为主”**：正文收敛争议细节，施工方法、资源配置、质量安全及验收措施仍写充分；正文、表格和图件采用同一有效清单口径。独立《冲突与待核实事项.md》记录原始差异、清单原文位置、采用口径和关联复验；编制处置与官方确认分开，已处理记handled，原始差异未获官方统一时照实保留。其他同层冲突继续比较文件效力、修订关系、版本、图号和适用范围，仍无法确定则记录影响和所需决定。

## 五、事实分类与写法

| 类别 | 示例 | 写作要求 |
|---|---|---|
| 项目约束事实 | 名称、地点、标段、范围、工期、质量目标 | 精确溯源并保持全文唯一 |
| 项目技术事实 | 工程量、尺寸、材料、结构、设计做法、场地条件 | 标明资料版本和适用部位 |
| 企业事实 | 人员、业绩、荣誉、设备、制度 | 有证明且身份呈现允许时使用 |
| 规范性事实 | 规范编号、版本、控制值、验收要求 | 核验有效性和项目适用性 |
| 计算结果 | 工程量/有效产能推导的工日、工期或资源量 | 留公式、输入来源、单位及有效作业条件，不伪装成清单原值 |
| 专业策划 | 施工分区、流水组织、资源配置、拟用工艺 | 明确为拟采用方案，不伪装成既定事实 |
| 未知或冲突 | 缺失、模糊、矛盾、无法确认的信息 | 内部登记；图纸瑕疵/与清单冲突按清单处置，其他影响正式正文的事项质询，不猜测 |

## 六、防污染与变更传播

使用参考标、历史项目或旧稿后，检查其他项目名称、地点、单位、标段、工期、规模、工程量、材料、人员、设备、业绩、图号、规范版本、页眉页脚、图片水印和文档属性。

关键参数变化后：

1. 更新唯一参数及变更依据；
2. 搜索目录、正文、表格、图注和页眉页脚；
3. 更新评分映射和相关知识库条目；
4. 复核由该参数派生的进度、资源、风险、措施和承诺；
5. 记录已复核范围，避免形成第二套事实。

## 七、关键参数跨来源核对

对正文拟用的控制值，在总说明、分专业说明、详图/结构图、材料表、清单及有效补遗中搜索相关出现，扫描页必须回看原图。登记每个数值的对象、适用部位、单位、版本、图号/页码及性质：项目事实、规范控制值、计算结果或拟采用措施。计算留推导，拟采用措施说明适用条件与可行性；有真实依据的计算和策划不因清单未逐字列出就判伪精确。不同部位可能采用不同值，不能仅按数值不同判断冲突，也不能凭“总说明优先”或“取高值”消解差异。图纸瑕疵/与清单冲突按本文件第四节处置，记录为何采用清单；其他差异解释适用范围或有效确认依据。

机器只能检查已登记项目，不能保证找全每处图纸参数。全篇版式PASS与技术溯源PASS是两类证据。

## 八、原资料全范围提取与反查

依次完成以下动作，复用现有startup、requirements、项目评分清单和内容核验，不另建重点台账。

1. **先固定检查范围。** 对照实际原资料目录、招标附件总索引及用户提供记录盘点有效文件；未取得附件、不可读原件、扫描图未识别均留未完成状态，不得用知识库摘要替代原件。source_scope列明实际输入目录，目录中每个文件纳入sources或给出排除理由及哈希；归档包先展开核对，容器与成员保留对应说明。输出、状态及读取缓存放输入目录之外，禁止用排除项隐藏重要附件。
2. **遍历原文再筛重点。** 用source_coverage.py独立枚举PDF页、Word正文/表格及附注、清单各工作表的非空行；包括隐藏表/行、总说明、项目特征、措施费/不可竞争费/其他费、批注、合并及公式信息。按原文逐单元识别事实、范围、义务、限制、工艺、风险、检测验收、费用保障和专业接口，不仅搜索名称、数量或评分关键词。图像/版面和公式回看原件，缓存缺值不推算报价金额。DWG等不可直接枚举格式须提供与原件绑定、经完整对应核验的可读转换件；失败明确阻断读取完成标记。
3. **从评分反向再读。** 从招标及有效补遗逐条保留评分项、评判子条件及优秀档要求到既有项目评分清单，再回全部原资料寻找项目化支撑；结合全部施工对象核对必要工序和接口。评分未点名的费用保障、验收义务或小分项仍须识别，不能为追求评分只提取高权重事项。
4. **每个重点有去向。** 拟纲按表名或表内标题识别全部「分部分项工程量清单计价表」，优先阅读其项目名称及特征，术语与标题映射按02第三节。 原文单元处置为requirements或有依据的no_technical_response；仅同文件、同处置逻辑的连续/同类单元可合并，不能整表一句“已读”概括。商务事项与技术实施义务分别判断，不把费用表整体排除。每条重点记录原文引文、单元ID和具体论述完成条件；可合并回应多条要求，但保留各自定位及独特工序、风险、验收条件。所有评分子条件各设唯一主响应需求，清单等支撑需求通过score_refs关联；施工必要而未单列得分的内容仍进入模块。事实冲突沿用第四节口径，有可执行处置则继续，不编造官方结论。
5. **把充分性变成完成条件。** 按每项实际需要选取对象、方法、资源、控制条件、检查验收、接口、异常处置或资金安排，写成具体response_requirements；不机械给所有需求套七个字段。模块完成时逐条件给出当前施工措施引文和判断依据；“严格执行”“符合规范”或同名标题不能单独证明充分。
6. **定稿独立反查。** 重新从当前原件逐页/逐表核对原始范围，找首次提取遗漏、遗漏响应或论述不足；再按评分子条件检查优秀档证据，并从正文反查事实/规范/计算/策划依据及图文一致性。发现新重点补入原requirements、模块和篇幅，定点返修并复查受影响证据。最终同一source_response_review覆盖全部原件及需求，不能只检查首次提取清单。未完成且影响响应的事项不得正式放行；脚本核完整性与引文绑定，AI负责语义和技术判断，不承诺自动零遗漏。

例如安全文明施工费须落实投入、使用安排、责任、审批台账及专款检查；金额引用须核实计取基数及来源。场地不具备堆场/加工条件须落实场外供应加工、运输卸料与进度资源衔接；覆土前测绘及CCTV须进入实施时点、责任接口、停止点、报告和工期安排；小型标线/收边可合并编写但保留具体做法与验收。例子仅解释提取和充分性，不构成所有项目固定章节。

## 九、清单引用的原行与反查

盘点全部有效专业、分册及修订版，用实际表名或表内标题定位，核实表头、工程名称和行号。保留带前导零的项目编码，分别登记项号、项目名称、特征、工程量和计量单位。编写明示引用时直接从该行取实际采用的字段。有效版本或专业仍有争议的先登记影响，继续处理可确认的内容。

定稿逐段、逐表行、逐图注阅读。一个位置引用多项就按各自短引文分开登记，包括只写名称、特征、数量或单位的明示引用。核原表字段及该处实际表达的部位和工序。文本扫描辅助找漏，编制者承担纯语义引用与变体的逐项核查。差异记录保存Word块／表行、原文、版本、专业、原表名、原行、字段和两侧值；错码、错项、错版、无法定位均退回修改。

泾县医院原始装饰清单的工作表“3.2 E.1 分部分项工程量清单计价表(所有标题)”中，第50行是第1项“拆除工程”，编码011606003001；第417行是第45项“嵌缝、打胶”，编码010518017001，1项。后者针对病房卫生间瓷砖与洗脸盆及门框边缝。测试样本仅摘取相关单元格，实际项目一律绑定完整有效原件。
