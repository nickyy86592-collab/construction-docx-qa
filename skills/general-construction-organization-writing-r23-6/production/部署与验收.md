# GH、Word Runner 与私有 GD 部署

两个 ZIP 可各自安装为编制技能。正式生产一次性把两个已解包目录注册在同一个受控私有 GH 仓库，同一 Windows Word Runner 可执行两版。配置前可继续使用原工作目录编制底稿。只有受控运行号和真实 Word 回执能入正式链路。

## 一次性登记

- 使用私有生产仓的默认分支。修改工作流、配对表、批准文件的权限交由维护人。编制身份用可调度 Actions、无法改写生产代码的授权，依据配置的仓库和默认分支调用。
- 选已登记的 Windows Runner 标签 self-hosted、Windows、X64、word-audit。用平常执行 Word 的同一账户安装/激活 Microsoft Word，并可访问私有 Drive 和受控依赖安装路径。
- 建立私有收稿、回执、暂存和正式四个目录。暂存让发布身份单独访问。实际普通编制身份在收稿可写、回执可读、正式目录只读。发布身份可取收稿并写其余目录。保留真实普通GD账户与受控发布账号的独立授权。正式与暂存放在允许整批移动的同一 Drive 内。
- 将两份 OAuth 刷新配置作为 construction-production 环境的 CONSTRUCTION_DRIVE_AUTHOR_OAUTH 与 CONSTRUCTION_DRIVE_PUBLISHER_OAUTH 秘密。每份 JSON 为 client_id、refresh_token 和必要的 client_secret。编制授权应能代表日常账户验证实际写入能力。生成 Ed25519 密钥对，公钥的 32 字节 Base64 写入配置，私钥种子的 32 字节 Base64 存为 CONSTRUCTION_SIGNING_KEY。秘密通过受控授权注入。
- 复制 release-trust.example.json 为实际私有配置，填仓库、默认分支、公钥与四个目录 ID。用审核主机或可信本地的 Python 3.12 从任一包执行。编制端校验签名需要 cryptography 42 以上版本。

```bash
python production/register.py --repository-checkout 私有仓本地检出目录 --settings 私有配置.json r22.6解包目录 r23.6解包目录
```

注册写入 review-runtime、版本配对表和 construction-versioned-release.yml。核对两版指纹，提交到已授权的生产默认分支。供编制端一次取得生产配置。后续只选编制版本，按每个项目自身的招标信息建立任务。同版审核文件按指纹保持，变动审核实现时登记新的版本并验证配对。

## 公开 GH 仓继续作为发起入口

现有 GH 仓可以继续公开。把同一台 Windows 电脑的 Word Runner 接到独立的私有生产仓，供两版使用。结束旧任务后迁移旧生产 Runner 的注册，让带生产授权的 Windows 实例仅接私有仓。公开入口使用 GitHub 托管的 Ubuntu 执行转发。公开仓传递私有文件的 ID 和摘要，Word 稿件、规则、回执与正式文件走私有 GD。

在私有配置额外登记 `"gateway": {"repository": "OWNER/PUBLIC-REPO", "branch": "main"}`，注册命令加 `--gateway-checkout 公开仓本地检出目录`。注册程序为公开仓写入入口工作流和转发脚本，分别提交到两仓各自的受控默认分支。仅向编制端提供它所需的受信配置。公开仓配置 `construction-dispatch` 环境，仅允许受控默认分支，对应环境 Secrets 为 `CONSTRUCTION_PRODUCTION_REPO`、`CONSTRUCTION_PRODUCTION_BRANCH` 和 `CONSTRUCTION_FORWARD_TOKEN`。转发令牌限用于私有生产仓的 Actions 写权限。Word、Drive 和签名相关的生产凭据留在私有生产环境。编制端的 `CONSTRUCTION_GH_DISPATCH_TOKEN` 按公开入口仓发起任务。私有生产仓然后依据冻结任务单选择两版之一并执行。

## 部署验收

在授权的账号及测试目录执行 check-acl，实际用普通身份提交一个无敏感内容的试件并确认 Drive 拒绝。按生产路径测试试排、实际测量、整批发布及回执取得。

```bash
python review-runtime/runner_release.py check-acl
```

验收用例为真实路径下合格整批发布、单点11页、缺一个点、无实排或替用旧回执、用错版本或替换冻结文件、普通账号直传及暂存上传中断。前一个示例应带正式链接，后面各类保持失败。用于调试的样稿显式走 probe，生产缺稿、缺规则或版本不匹配记录 FAIL，不转为回归测试。GH 正式日志仅登记运行元数据和结果，项目输入、报告、诊断和完成件通过受权的私有 GD 传递。两份包提供本地回归用例，实网部署前须核当前 Windows Word 会话和 GD 权限。

若使用公开入口，再从它发起两个项目的试排，确认私有收发可用时收到与版本配对的真实 Word 回执。用隔离测试目录模拟私有收发权限不可用，核对两版均未正式发布且公开运行没有项目稿件产物。
