# 优秀区间评分、实景图占位与图文优化（按阶段读取）

此文为专项操作约定；正常编制先读 `SKILL.md`，涉及评分解析、实景图安排、占位替换时再读取本文件，避免每一章重复加载。

## 一、评分：AI 解释原文，轻量脚本只校验客观信息

1. 首次研读招标文件及有效补遗后，AI 提取评分项目、满分、优秀分值区间、评价要素原文、页码/条款位置。复杂句拆成子条件。若招标没有明确优秀分值区间，记 `excellent_range: null` 并说明原因，绝不补造。
2. 建立当前项目运行期 `项目评分清单.json`，不内置 Skill，也不让用户手工编辑。模块完成时引用同一清单的评分原文/优秀条件，把措施针对性、深度、项目依据及实质响应的轻量复核结论写入既有模块记录；缺项先补强，无明确优秀条件时据实注明，不编造条件。后续40%、75%、完稿复用同一清单；仅在发生有效澄清、补遗或正文修改时增量更新。
3. 已完成条目才可以模拟评分。先逐条反查技术措施、资源与工期、可靠项目事实以及正文定位，按优秀区间条件说明得分与扣分风险。未完成条目保留 `pending` 或 `partial`，阶段不能把未完成部分计分或机械外推全标得分。
4. 40%与75%评分诊断和 Microsoft Word 真实页数校准同阶段进行，不新开阶段；复用已通过且未变更的模块记录，重点核对跨章节关联、评分覆盖及内容篇幅；对已完成但有失分风险的内容优先补强，和篇幅预算联动。自评分不得为了达到优秀而虚高。用户无需参与 JSON 的日常维护。
5. 成稿完成时逐项自评并生成**单独的《施工组织设计技术评分模拟自评报告》**：评分标准引用、每项满分/优秀区间、模拟得分、正文证据位置、为什么给该分、可能扣分理由、分数总和及不确定性。报告默认不插入投标正文；若某项高度主观，应明确为模拟判断而非承诺。
6. 使用 `scripts/评分响应核验.py` 做范围、算术、来源、评分条目与证据定位校验；它**不读取招标原文、不评估施工技术、不联网、不打开 Word，也不改变分数**。例如：

   `python scripts/评分响应核验.py 项目评分清单.json --phase 40 --document stage-40.docx --report 评分40.json`

   `python scripts/评分响应核验.py 项目评分清单.json --phase 75 --document stage-75.docx --report 评分75.json`

   `python scripts/评分响应核验.py 项目评分清单.json --phase final --document final.docx --report 评分最终.json`

  `FAIL/ERROR` 表示评分信息或核验数据不可靠，应补齐后复核；`PASS` 仅表示结构与算术合格，**不等于模拟分数被专家认可**。如果报告有 `WARN`，需说明处理结论。

### 项目评分清单数据格式（示例，不得把示例数值用于真实项目）

```json
{
  "tender_source": "示例：招标文件2026年修订版／评标办法第xx页",
  "declared_self_total": 9.2,
  "items": [
    {
      "id": "A1",
      "name": "施工方法（示例）",
      "source_ref": "示例：评标办法第xx页第1项",
      "max_score": 10,
      "excellent_range": [9, 10],
      "criteria": ["示例：施工方法贴合项目", "示例：工序和资源安排相互匹配"],
      "completion": "complete",
      "evidence": [
        {"location": "第二章第一节", "response": "示例：针对某工序的施工步骤和控制措施"}
      ],
      "self_score": 9.2,
      "reason": "示例：全部两项优秀条件已提供具体响应",
      "excellent_justification": "示例：工程工序、控制措施、设备配置及检查点构成闭环",
      "deduction_risk": "示例：现场条件如变更，需复核措施适用性"
    }
  ]
}
```

`excellent_range` 在招标原文未明确时填 `null`，并补充 `excellent_note`；评分项目没有写完时将 `completion` 设为 `partial/pending`，`self_score` 暂不参与阶段合计；只有真正完成才改 `complete`。

## 二、按项目整体选择实景图或示意图

1. 一般情况下，AI从整个项目判断实景图是否能丰富文档、佐证施工环境/技术难点或提高评分响应质量；更适合照片时选择最有价值的主题（有真素材插图，无素材留占位），更适合示意图时直接生成针对性示意图，照片清单可为空。不能因缺照片就自动判不需要，不能把三张必备图充作替代主题；替代示意图可计入默认额外1—3张功能图。**不按一级章节平均分配照片数量**。非一般情况按临时提示词、AGENTS.md明确要求确定，招标硬要求优先；决策及依据写入visual_policy。
2. 初稿阶段按需生成灰底细边框的**真实照片占位框**（优先正文流中的一格边框表格），中心注明“需插入现场照片”，附明确主题（如“拟插入现状排水沟照片”）及必要拍摄对象说明。占位可临时包含可识别的 `【实景图占位：拟插入现状排水沟照片】` 文字，让硬审识别；正式稿替换后必须去掉此占位标记。照片位宽高兼顾 A4竖版与可读性，无必要不独占整页。
3. 正文及附录的图、表各自按实际出现顺序从1连续编号。每个独立图件（含照片、照片占位、示意图）设「图1 图名」类图题，每张内容表设「表1 表名」类表题。图号、表号各用一套序列，不按章或类别重置。图题贴图、表题贴表，默认图题在下、表题在上。组合图先合成一幅再编号。纯排版框不作为内容表；跨页的同一张表保留原编号并使用重复表头。
4. Word 优先使用各自的 `SEQ 图 \* ARABIC` 与 `SEQ 表 \* ARABIC` 域，生成时填入正确显示缓存。增删、移动或替换图表后统一更新题注、交叉引用及图表目录（若有），保存交付副本后复核实际显示值。禁止跳号、重号、图X或表X等未定编号。
5. 选择的照片/占位、替代示意图及额外功能图与三类必备图一起计入前置图表篇幅估算；Word 40%和75%阶段快照保留所选方案的预期图文空间，不强制无照片方案额外造照片框。
6. 用户提供真实实景照片后，在**原占位框位置**替换；保留原图号和图题，核对拍摄部位、文件与来源，记录照片来源 `source_record`。**严禁 AI 生成、冒用相似项目实景或无依据声称照片真实。** 选择照片且缺素材时保留带框占位并交付待补照片编制稿；不得为通过审核临时删框。正式投标版须补齐所选真实照片；确因新的整体判断或有效特殊要求改用示意图/省略时，同步记录决策依据、清单、替代图及图号，复测受影响证据。
7. 运行期项目格式审查规则（非页数规则）中，`required_real_photo_slots` 保存当前有效项目判断及特殊要求确定的照片主题（有效无照片方案为[]），每项可含 `name`、`keywords`；第二轮替换完成后标记 `replaced: true`、`source_record: "用户提供的照片文件名/素材登记记录"`。`photo_delivery_stage: "draft"` 允许占位，`photo_delivery_stage: "final"` 时残留任意 `【实景图占位：…】` 将被 FAIL；照片附近必须确有图片和来源记录。脚本无法独立证明真实拍摄，必须人工回查素材。

### 用户补入实景照片后的局部复审（第二次处理）

当用户已经在上一稿中提供并替换实景照片，直接启动 `SKILL.md` 的“实景图替换复审”分支：**不运行 init / preflight / 40% / 75% 阶段重置**；确认照片确系本项目真实素材（材料不足则明确提示无法确认），原位替换后的图片和图题编号匹配并更新域/交叉引用。审查规则设置为 `photo_delivery_stage: "final"`，有替换的每个要求项都需有 `replaced: true` 和真实来源登记 `source_record`，不得以只添加来源文字冒充图片。最终必须对调整后的 Word 重新渲染、重新执行通用格式硬审与独立项目页数硬审。不得通过临时清空照片清单规避审核；新的整体判断或有效特殊要求确需变更时，同步更新visual_policy、清单、替代图及图号，并复测受影响证据。该局部分支最终检查范围保持原规定。

在没有 Windows Word runner 在线时，可以先做文本/图号等预检查，但不能将 LibreOffice 估值称为最终 Word 双硬审 PASS；只有实际 Word 审核通过才算完成二次复审。

**远程执行（如已配置）**：使用通用工作流`Word formal delivery audit`，运行期文件放`input/project/`。AI提交本项目生成的`format_rules.json`及当前唯一项目页数脚本；工作流不保存专业、章节、字体、照片主题或页数默认值。手动photo_stage选择draft/final；push触发保留格式规则已有阶段。每次须传本次visual_policy及相应照片清单（有效无照片方案可为空）；正式版对所选照片检查来源和替换状态，对示意图方案检查实际图件，不得临时清空清单规避审核。新增visual_policy.py也须随通用脚本一起提供给远程执行环境。

## 三、图文版式优化与 Word 复验

- 创建必备三图、增补或替代示意图及适用照片框前，按A4竖版正文宽高预估图的比例、字体字号、图题长度和前后内容，避免整图溢出下一页。网络图突出关键线路，配置图例，优先优化节点分组以保持可读性。按已核实空间关系绘制布置图。尚无依据的点位登记为资料缺口，已核实部分可先绘制；指定必验点位补齐后再正式放行。
- Windows Microsoft Word 实测时，图片前页底剩余空间约**20%**起触发优化提醒（`WARN`），1/3且符合“下一页靠近页首出现图片、图片前文本较少”的组合证据才走已有迁移型 `FAIL`。数值是相邻页图片迁移检查的**非招标初始参数**，需结合样稿校准。总页数末页另执行04规定的留白硬审。
- 检查规则还识别一格表格构成的照片占位框，尽量输出前页与图页的页码及 Word 版式证据；几何无法核实不应报成已通过。
- 优化优先级：段落图题绑定/不合理段前段后距 → 图片在同页更合适的位置 → 调整纵横比例并重绘图形信息 → 调整邻接解释文字；不得强制分页、创建横版、编造空白文字或降低可读性。
- 实景图后期替换和图件尺寸/位置修改会引起重排，**同一轮相关修改完成后统一重排，并同时复验Word正式格式硬审及独立项目页数硬审**；不逐张或逐次小改重跑。样章及40%/75%既有门禁不推迟，阶段提交、切换交付或最终冻结前结束本轮并复测；最终冻结文件完整验收。后一版发生改变时，旧PASS不代表新文件合格，重跑受影响检查。

## 四、彩图与语言复核

默认三张必备图及额外1—3张功能图均须彩色，颜色作用于主体分区/工序/关键线路，不能用彩色角标代替。AI从整个项目自行选择功能图题材、生成图片并衔接上下文，不用装饰图充数；替代照片的针对性示意图可计入增补图。临时提示词、AGENTS.md或有效招标有特殊要求时，按visual_policy中的有效依据执行相应配色和增补数量。静态核验读取实际嵌入图的配色并检查增补图实际说明，AI须查看全部图件及Word渲染页面确认功能、主体可辨识和逻辑衔接。正文逐段转换成施工执行语言，机器明确词筛仅为辅助。照片真实性警告必须以原始素材及来源复核记录处理。

## 五、实际图面逐项复核

编前为每种指定图建立必验要素。总平面在同一图面辨认作业区、出入口、实际路线、适用临设及空间关系，按项目增列消防通道、垂直运输等要求，并回查底图、会签图或踏勘记录。网络图核关键活动、方向、紧前关系和技术间歇；横道图核工序、作业时段及搭接。其他指定图按招标原文逐项定条件。

插入Word后用实排页查看图上文字、线、箭头和边界，按总页、图号、图上位置、可见内容留下复核结论。图名正确而图内仅有施工步骤框，或必验关系无法辨认，退回重绘。换图、换页或数据改变后重核受影响证据。有适用例图时查看布局、图例和表达；无样图时直接按指定图种、原始资料和必验要素绘制。
