# 通用施组编制（天一）

有效版本：2026-10-22-r6（格式硬审1.8.4；状态schema 3.1，旧状态保留）。

## 1. 执行契约

将“编制、续写、定稿、生成Word”按正式生产任务执行。以施工单位为主体写出可实施方案。**除项目页数硬审脚本外，本包只保留通用编制与审核逻辑。** 名称括号仅标识当前配套页数脚本，不绑定工程专业。换项目只需替换页数脚本；同时按正常编制提供该项目资料，由AI自动生成运行期章节、格式、照片及参数记录，不要求用户修改通用Skill或通用脚本。专业知识由项目资料、领域知识库和经核验规范提供；参考标只借鉴写法，不继承事实。不用框架、重复表格、内部编制说明冒充正文。

**强制要求：开工前质询；优先一次、最多三批交付；三张彩色技术图；实景照片或有主题的带框占位；关键参数跨来源核对；正文施工语言；最新文件核验；审核报告绑定实际文件。** 招标硬性要求优先；若禁彩图、禁照片或与用户要求冲突，登记冲突并先解决，不能自行省略。

Skill负责判断和调用；脚本负责客观拦截。脚本不能证明专业判断、来源真实性或模型始终遵守指令。不得声称安装后绝对不会绕过要求。

## 2. 任务分支与环境

先判定任务目的：
- 首次编制/全文实质重编：执行第3—7节全流程。
- 已有稿的局部图文返修/照片替换：保留原阶段状态，**不重新init，不重跑40%/75%**。读取当前要求和新稿，检查变更影响、照片来源、图号及新发现参数冲突，执行新稿静态核验、内容溯源、Word格式/页数和delivery局部分支。

首次读取[运行字段与调用](references/04_门禁字段与调用.md)，选择可实际执行的Word通道：Windows环境且能调用本机Word COM时直接运行包内脚本；网页版已有GitHub/Windows Runner链路时复用远程执行。**电脑装有Word不等于当前会话能调用Word。** GD、本地目录或其他授权文件源用于读写资料；不默认某个固定账号、目录或仓库。GitHub不是桌面端必需项。

预检依赖与Word调用能力；不得每轮重复安装/下载。一次失败后保存阶段稿、状态和报告，定位原因，只重试有明确修复依据的步骤。Runner离线时允许LibreOffice临时估值，标PROVISIONAL；最终Word验收仍必须实测。真实故障未关闭不得假报PASS。

## 3. 开工前必须完成的动作

1. 盘点文件及版本，读取[资料判断与事实控制](references/01_资料判断与事实控制.md)。先穷尽现有资料，不把检索转交用户。
2. **集中主动询问是否还有最新澄清、答疑、补遗、补充文件及提交系统新要求**，同时提出影响工程范围、技术路线、评分或确定性承诺的关键问题。当前会话用户已明确答复的事项引用答复来源，不重复问；不得把沉默写成“没有”。尚未回复时继续资料整理、检索和规划，禁止依赖未确认信息写正式正文。
3. 判断一次完成能力；优先一批，确需拆分时说明原因、规划2或3批及各批内容。**最多三批只限制用户交付；内部模块写作、保存、样章、40%/75%快照、校准与返修不限次数。** 不将全文拆成超过三批。
4. 先识别招标及有效补遗的封面结构、目录层级、标题体系和正文起始要求；未明确时默认封面与一级目录共第1页、正文第2页开始。AI自动生成项目格式规则，目录、正文标题及Word导航一致；不得要求用户改通用脚本。第一项页数相关动作读取项目独立页数硬审脚本。该脚本是正文范围与封面/目录扣除页数的唯一来源；以真实Word导出页面核对封面及完整目录实际合计页数，不能直接沿用脚本示例扣除值；不一致先修正该项目脚本并重测受影响证据；自动识别当前唯一脚本，不硬编码脚本文件名或页数。换项目仅替换该脚本，禁止同时保留两份项目页数脚本。没有项目页数脚本仍执行启动、图件和内容门禁，只跳过页数规划与阶段页数校准。
5. 执行`编制流程门禁.py init`。由AI填写状态：资料版本/哈希、最新文件问答来源、关键问题关闭结果、交付批次、Word通道、照片主题清单及篇幅规划。初始BLOCKED/退出码2是预期；禁止为消除报错而写虚假确认。
6. 按第4节先建立内容模块与预算，再运行`preflight`。目标正文达到200页的长文只输出`PILOT_DRAFT_ALLOWED`，仅允许代表性样章；通过真实Word试排、预算校准及`draft-ready`后出现`PRE_DRAFT_ALLOWED`，才批量编制正式正文。较短项目仍须完整内容规划，preflight通过可直接编制。旧状态缺真实启动或模块记录时据实迁移，不能伪造历史。关键问题仍悬空则停止依赖部分并请求实质答复。

## 4. 评分、篇幅与阶段保存

读取[评分映射与长文编制](references/02_评分映射与长文编制.md)，建立“评分原文/子条件→主响应章节→项目依据→施工措施/证据”。招标指定目录优先；三级标题默认第一章、第一节、一……，使用Word真正的标题样式/大纲级别形成侧边导航。二、三级数量服从内容，禁止机械3×3。目录默认显示页码，用真正的点引导符和统一右对齐制表位，不用空格/手打句点拼接；多级目录只调整左缩进，长标题自然换行、页码不得孤行或越出版心。招标/有效补遗另定格式时由AI记录依据并适配；细节及Word复核见[运行字段与调用](references/04_门禁字段与调用.md)。

**先规划内容，再预算篇幅。** 首次/全文重编必须读取[内容模块与长文规划](references/05_内容模块与长文规划.md)。将评分子条件、施工范围、必备工序和强制响应逐项落到“章—节—实质内容模块”，每项只设一个主响应位置；逐模块明确依据、技术深度、接口、正文字符估量及文字/表格/图片空间。判断项目资料和施工内容是否足以支撑要求的篇幅；有容量缺口先补资料或解决冲突，不靠空白、重复表格、案例事实或拉大行距填满。

有页数脚本时，全篇预算必须在**该脚本最终允许的正文范围**内；模块预算合计加机动量必须等于全篇规划值，章区间应涵盖所属模块。图表已计入模块，汇总统计不能再次加页。模块上限由通用脚本按项目目标派生，过大单元按实质工序/责任拆分；禁止只填一个总页数或按章平均分配。无页数脚本仍须内容需求、模块与容量判断，只跳过页数预算与测量。

长文在批量正文前从至少两个真实模块选取代表内容，覆盖正文、表格、彩色图及照片框，以本项目正式格式生成小样。按脚本派生的样章范围调用Word实际重新分页及导出PDF，逐页查看字体/行距、表格、图件和照片框；执行`pilot`登记报告与分析。依据实测文字密度重算全部模块预算及阶段区间，修改规划后重新`preflight`、`draft-ready`。样章可复用到正式正文，复用部分仍须模块核查；格式或样章失效必须重新校准，禁止拿LibreOffice估值通过长文样章门禁。

每个模块完成立即保存真实正文源和复核记录，执行`module-checkpoint`；检查依据、技术深度、接口、重复和施工语言；承担评分条件的模块立即对照评分原文及优秀条件，检查针对性、技术深度、项目依据和实质响应，缺项及时补强。把结论及施工措施原文定位写入同一模块复核记录，跨模块未完条件登记责任位置、不强行评分，供阶段复用。保存哈希、正文探针及实际文字量。模型滚动预测异常先复核内容与图表预算，必要时提前Word测量；模型预测属于估算，不能当最终页数。恢复时读取模块登记、来源版本、参数台账和最后有效状态，禁止丢失已写正文或从头重新生成。

脚本阻断跳过阶段节点继续登记后续新模块。约40%和75%的节点按已完成内容/评分责任选择连续模块前缀，预先登记模块ID、完成度依据及预算派生区间；不是用当前页数除以百分比猜整本。保存实际合并DOCX，通过本机Word或远程Runner重新分页，运行`checkpoint --stage 40|75 --document 阶段稿 --report Word阶段报告`。报告须匹配快照、阶段和当前页数脚本；模块源必须存在且正文实际进入快照。除阶段区间外，**已实测前缀＋剩余模块预算＋机动量**也必须落在最终范围。全局校准重点检查跨章接口、评分覆盖及内容篇幅协调，复用已通过且正文/依据未变的模块记录，只增量复核变化项。同步用评分清单执行`评分响应核验.py --phase 40|75`，只评已完成项。

75%前先完成40%校准；FAIL/旧模块使快照STALE时禁止盲写下一模块。按真实测量返修内容、调整剩余预算，重新规划准入并复测，不能只扩大容差。Word暂不可用时，阶段稿可用`--actual-pages N --engine libreoffice_estimate --allow-estimate --document 阶段稿`登记PROVISIONAL，最终前补Word实测；长文早期试排要求不因此免除。不能全文完成后补造历史节点。

最终合并时执行`final-ready --document 最终稿`；逐模块核对源与复核记录、正文探针和主体内容是否进入实际DOCX，复核两次Word阶段证据及当前来源。不能用只含探针的缩略稿冒充完整合并。内部校准保存正文源、DOCX、规则、评分清单、状态及恢复点，全部用户交付仍最多三批。

## 5. 必备三图与实景图

**必须在正文实际嵌入施工功能分区示意图、施工进度横道图、施工进度网络图，三图均采用彩色。** 制图前查看`assets/examples/`的当前三个同类例图，借鉴其配色、图例和视觉层次。参考图片保留原示例工程内容，仅作视觉样式参考；不得复制名称、专业、数量、日期、工期或位置。使用可核验数据由AI策划并用代码/矢量绘图；进度网络等精确图不使用随机生成式图片。

颜色须用于分区、工序、阶段、关键线路等信息主体，不能仅给标题或一个角标上色。默认多种可辨识色系，网络图突出关键线路并配图例；灰黑图不合格。招标明确限制颜色时记录原文并关闭规则冲突。例图仅供样式，不直接当项目图，也不继承其日期、方位、工程量、布置或工期。横道图和网络图从本项目工序依赖、工程量及人材机产能推导工期、节点参数和关键线路，计算逻辑须可复核；三图共享正文中的进度/资源数据；图上无依据的位置写“示意、不按比例，具体位置待现场确认”。

未有相反招标硬性要求时采用全篇A4竖版，图件竖向组织，不用横版页面或过宽横图；网络图分组/纵向排布，横道图收敛时间列。按实际插入尺寸核对中文字体及最小文字可读性。

**实景图必须有：已有可确认真实项目照片则插入；缺素材时，编制稿必须留下带边框、明确主题、标注“需插入现场照片”的占位框。** `required_real_photo_slots`至少一项，位置按技术价值选择，不按章平均。照片主题从当次工程对象、关键施工环境、接口和技术难点选择；不得固定沿用其他项目主题或虚称现场情况。

占位建议用有可见边框及预留高度的一格表格，含`【实景图占位：主题】`；照片/占位与三图共用连续图号，优先SEQ域并核对缓存显示。不允许仅写一句“需照片”、照片清单为空、因招标未点名就省略，或自行删除已约定占位。不得AI生成实景，不得冒用其他项目照片。

区分交付：含占位的文件标“待补现场照片的编制稿”；正式投标版`photo_delivery_stage=final`必须真实照片、来源记录及人工核验，任何占位残留都阻断正式投标。用户明确修改照片要求或招标禁止时登记依据并更新清单，不能由AI自行裁减。

细节见[评分与实景图](references/03_优秀区间评分与实景图.md)。图前/相邻页留白20%提示优化，约1/3且有迁移证据判FAIL；检查Word导出页面证据、改位置/比例/段落绑定后重审，不强制分页、不空段凑页、不缩到不可读。

## 6. 内容事实与施工语言

事实必须可溯源，专业策划必须明确为拟采用措施。遇评分原文/否决项、知识库冲突、具体数字条款、点名重难点、待核实资料、企业资料、规范控制值、初稿审查和最终最新文件核验，按用户十项回查规则查原文。

**对用于正文的关键控制参数，不能只查一个出现位置。** 在总说明、专业说明、详图、结构图、材料表、清单、补遗中检索同对象的所有相关出现；扫描图需目视/OCR后回看原图。记录对象、适用部位、数值、单位、版本、图号/页码及候选差异。先区分适用范围，再比较文件效力；不能凭总说明覆盖详图，也不能自行取高值。

发现同一参数不同数值时，先核对对象、适用部位和有效版本，再登记候选值及决定依据；未关闭的差异不得写成统一控制值。不把参考图或历史案例的数据当作当前项目事实。

逐章检查部署、方法、进度、资源、质量、安全、图表和承诺一致。核心内容写“对象—工序—操作—资源—控制—检查—偏差处置”的实际施工逻辑，不机械套相同字段。

**按模块复核施工语言，正式正文不得混入审查意见、待办提示、自我评价或内部状态。** 如“差异尚未闭合”“本章需进一步完善”“建议补充相关措施”属于典型内部审查表达；“疑似符号”须结合上下文判断。这些只是边界示例，不是封闭词表。正常的“监理审查意见落实后组织复验”“发现疑似裂纹，复检确认后处置”等施工表达应保留。少量示例明确边界，AI负责语义判断，脚本负责高确定性拦截（FAIL）和语境疑点提示（WARN）；不得机械删除。对异常段落定点修正为材料报审、工序检查及偏差处置等真实措施；未解决技术问题放既有独立冲突记录，据实处理并停止依赖部分，禁止编造事实掩盖冲突。最终逐段语义复核并处理全部提示，未处理内部语言不得交付。

## 7. 最终门禁与交付

1. 在交付副本中更新完整目录及页码、保存并重新分页，核对目录/正文标题/导航与实际页码；查看长标题、页码右边界及跨页目录。前置页变化按唯一项目页数脚本校准并重测受影响证据，不能靠缩正文、强制分页凑回原页位。然后冻结DOCX及自动从本项目资料提取的`format_rules.json`；图件三项均hard=true、color_required=true；照片清单不得为空，明确draft/final阶段。规则不存页数目标；封面结构、目录层级和标题模式由AI从当次有效资料提取；前置页定位从当前唯一页数脚本派生，若与招标要求或Word实际前置页冲突，按依据修正项目脚本并复测受影响证据。先运行通用硬审`--static-only`检查真实嵌入图/配色/占位框/图号/内部语言；静态PASS不等于Word版式通过。
2. 执行最终内容强审，填写`内容溯源核验.json`：绑定新稿哈希，十项回查逐项留来源/位置/结论，关键参数候选值及适用部位、冲突处理依据、正文施工语言逐段复核、三图实际视觉复核。评分最终核验并单独输出模拟自评报告，不嵌入正文、不承诺评委分数。
3. 执行`content-review --document 新稿 --review 内容溯源核验.json`。脚本只核验记录完整性、来源文件哈希和冲突状态；遗漏的来源或错误专业判断仍须人工识别。未查原图不能标已核验。
4. 首次编制执行`final-ready --document 新稿`，然后对**同一冻结文件**运行Microsoft Word通用硬审及独立页数硬审。局部复审跳过final-ready和历史阶段要求，仍对新稿执行全部当前检查。
5. 最终确认最新澄清、补遗和系统要求；如果启动后又出现新版本，更新索引、正文、内容记录及全部受影响检查。不得沿用旧报告。
6. 执行`delivery --document 新稿 --static-report … --word-report … --page-report … --score-report … --review … --warning-review …`；无页数脚本不传page-report，局部模式另加`--mode local-review`。报告哈希必须匹配文件，规则指纹及照片阶段一致，WARN/SKIP逐条有处理证据。任何FAIL/ERROR阻断合格标记，返修后重跑受影响检查。
7. 含占位且审查通过只允许`DRAFT_DELIVERY_ALLOWED`；真实照片齐备且审查通过才允许`FINAL_DELIVERY_ALLOWED`。报告、评分自评和待补照片清单与投标正文分开。升级仅对新编/实际变更模块使用新复核字段，既有有效正文、状态及审核历史保留，不重置、不补造历史。Windows Word全链路未运行时如实标未完成验收，不能以PDF预审或脚本语法通过代替。
